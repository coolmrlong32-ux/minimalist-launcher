## 2. 边缘流体字母波浪与主列表联动 (`NiagaraWaveView.java` + `MainActivity.java`)

### 2.1 现有缺陷诊断

在 `v2.5.0` 的 `NiagaraWaveView.java` 中：
1. **波浪凸起算法过于生硬**：原有 `flatTopFactor()` 与 `factor()` 采用简单的分段线性折线 (`rampWidth = 9.5f`)，缺乏自然流体物理张力；波浪边缘存在明显折角，未形成正态分布平滑扩散。
2. **手势排除区（Exclusion Rects）覆盖死区**：当前 `updateDynamicExclusionRect` 仅根据单点设置了一个固定高度的矩形（200dp），当用户从顶部滑至底部时，排除区更新存在节流延迟，容易触发 Android 10+ 系统的全面屏侧滑返回手势。
3. **主列表与波浪脱节**：手指在波浪滑动时，主列表（`StreamAdapter` 中的 `ViewHolder`）仅执行 `scrollToPositionWithOffset` 硬跳转，列表项在 X 轴上静止不动，缺乏 Niagara 标志性的“聚焦项向屏幕内部被波峰推挤”的流体视差感。
4. **触觉震动反馈单一**：仅依赖普通震动，未针对高刷新率屏幕与低延迟马达做分级防抖（Debounce）处理。

### 2.2 高斯正态包络线与流体导轨算法

在 `v2.6.0` 中，采用严格的高斯正态分布包络函数替代分段线性折线：

$$f(y) = A \cdot \exp\left( - \frac{(y - y_0)^2}{2\sigma^2} \right)$$

其中：
- $y_0$：用户当前手指在导轨上的垂直触摸位置（平滑滤波后的物理触点）。
- $A$：波峰最大横向偏移量（推荐值：`maxWavePeak = 52dp`）。
- $\sigma$：高斯波宽标准差（推荐值：`sigma = 48dp`，波及范围覆盖触点上下约 3~4 个字母）。

```java
// 优化后的高斯波浪形变因数计算（Java 8 规范）
private float calculateGaussianFactor(float itemCenterY, float touchY, float sigma) {
    float dy = itemCenterY - touchY;
    return (float) Math.exp(-(dy * dy) / (2.0f * sigma * sigma));
}
```

每个字母绘制时的 X 坐标动态计算：
```java
float factor = calculateGaussianFactor(itemCenterY, mTouchY, mSigma);
float offsetX = - (mMaxWavePeak * factor); // 向左凸起（屏幕内侧）
float scale = 1.0f + 0.65f * factor;       // 焦点字母放大至 1.65 倍
float alpha = 0.45f + 0.55f * factor;      // 非焦点字母透明度衰减，焦点字母 100% 不透明
```

### 2.3 动态系统手势排除区（`systemGestureExclusionRects`）精准跟随

Android 10 (API 29) 引入了边缘系统手势排除区机制，单侧总高度限制为 200dp：
- 当手指未按下时，在屏幕右侧右下角（用户拇指最常触发区域）保持常驻 160dp 的排除区。
- 当手指按下并滑动（`ACTION_DOWN` / `ACTION_MOVE`）时，排除区矩形动态居中于手指当前的 `touchY`，上下各延伸 90dp（总高 180dp $\le$ 200dp 限制），确保用户上下滑动快速检索时系统永远不会误识别为系统返回手势。
- 手指松开（`ACTION_UP` / `ACTION_CANCEL`）后，通过延时 300ms 的平滑过渡将排除区重置为常驻区域，避免边缘手势死锁。

```java
public void updateSystemGestureExclusion(float touchY, boolean isTracking) {
    if (Build.VERSION.SDK_INT < Build.VERSION_CODES.Q) return;
    List<Rect> exclusionRects = new ArrayList<Rect>();
    int width = getWidth();
    int height = getHeight();
    if (width <= 0 || height <= 0) return;

    int right = getRight();
    int left = right - (int) dp(32); // 覆盖右侧边缘 32dp
    
    if (isTracking) {
        int top = (int) Math.max(0, touchY - dp(90));
        int bottom = (int) Math.min(height, top + dp(180));
        exclusionRects.add(new Rect(left, top, right, bottom));
    } else {
        // 静止状态，覆盖拇指黄金停留区
        int top = (int) (height * 0.45f);
        int bottom = (int) (top + dp(160));
        exclusionRects.add(new Rect(left, top, right, bottom));
    }
    setSystemGestureExclusionRects(exclusionRects);
}
```

### 2.4 主列表项横向内推位移（Inward Wave Translation）与微缩放

为了呈现 Niagara Launcher 标志性的流体推挤触感，在 `MainActivity.java` 的 `RecyclerView` 容器中建立双向联动信道：

1. **接口定义**：
```java
public interface OnWaveScrubListener {
    void onWaveScrubStart();
    void onWaveScrub(char currentLetter, float progress, float touchScreenY);
    void onWaveScrubEnd();
}
```

2. **主列表物理联动机制**：
当 `onWaveScrub` 触发时，`MainActivity` 遍历当前屏幕内可见的 `ViewHolder`（通过 `layoutManager.findFirstVisibleItemPosition()` 至 `findLastVisibleItemPosition()`）：
- 计算每个 `itemView` 的中心 $Y$ 坐标与导轨 `touchScreenY` 的距离 $\Delta Y$。
- 根据相同的高斯模型计算位移因数 $F_{item} = \exp\left( - \frac{\Delta Y^2}{2\sigma_{list}^2} \right)$（其中 $\sigma_{list} \approx 72dp$）。
- 对 `itemView` 执行即时平移与微缩放：
  - `itemView.setTranslationX(- dp(36) * F_{item})`：向屏幕左侧挤出。
  - `itemView.setScaleX(1.0f + 0.04f * F_{item})`、`itemView.setScaleY(1.0f + 0.04f * F_{item})`。
  - 对图标 `iconImageView` 赋予额外的视差平移：`iconView.setTranslationX(- dp(12) * F_{item})`。

3. **松手弹性阻尼复位**：
在 `onWaveScrubEnd()` 中，遍历可见项并启动 `ValueAnimator.ofFloat(1.0f, 0.0f)` 阻尼回弹，使用三次贝塞尔插值器（`PathInterpolator(0.25f, 1.0f, 0.5f, 1.0f)`），在 180ms 内无缝恢复 `translationX = 0` 和 `scale = 1.0f`。

### 2.5 触觉反馈引擎：跨越字符临界点的 `CLOCK_TICK` 极速微震

在滑动检索过程中，震动反馈必须与字母切换完全同步且无多余杂震：
- 记录 `char mLastHapticLetter`。
- 仅当且仅当手指滑入新的有效字符区间时触发一次极短震动。
- 针对 Android 8.0+ (API 26) 与旧版本做精确兼容分支：

```java
public void performWaveHapticFeedback() {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
        // Android 10+ 优先使用系统预定义 TICK 效果（轻脆微震，手感最贴合）
        try {
            VibrationEffect effect = VibrationEffect.createPredefined(VibrationEffect.EFFECT_TICK);
            mVibrator.vibrate(effect);
            return;
        } catch (Throwable ignored) {}
    }
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        // Android 8.0/9.0 使用 10ms 极微脉冲
        try {
            VibrationEffect effect = VibrationEffect.createOneShot(10, 85);
            mVibrator.vibrate(effect);
            return;
        } catch (Throwable ignored) {}
    }
    // 降级使用 View 原生 HapticFeedback
    performHapticFeedback(HapticFeedbackConstants.CLOCK_TICK, 
        HapticFeedbackConstants.FLAG_IGNORE_VIEW_SETTING | HapticFeedbackConstants.FLAG_IGNORE_GLOBAL_SETTING);
}
```

## 3. 单手右滑直达上下文 Pop-up 浮层 (`MainActivity.java` + `NotificationHubService.java`)

### 3.1 极简手势识别器：TouchSlop 与极角隔离

在列表项（尤其是首页 Favorites 收藏项与常规列表项）上，用户极易出现手势意图重叠（纵向滚动列表 vs 横向滑出弹出层）。
必须在 `MainActivity.ItemTouchListener` / 列表项的 `onTouch` 中实现严苛的角度与距离隔离：

```
                    纵向滚动 (Scroll List)
                           ▲
                           │  |dx| * 2.0 < |dy|
                           │
       ───────────────┼───────────────▶ 横向滑出浮层 (Pop-up Trigger)
                           │  dx > touchSlop && dx > |dy| * 2.0
                           │
                           ▼
```

**手势判定算法**：
1. 记录触摸起始点 $(X_{down}, Y_{down})$。
2. 当接收到 `ACTION_MOVE` 时：
   - 计算 $dx = X - X_{down}$, $dy = Y - Y_{down}$。
   - 若 $dx > 0$（向右滑）且 $dx > mTouchSlop$ 且 $dx > Math.abs(dy) * 2.0f$：
     - 判定为**右滑呼出意图**。
     - 调用 `requestDisallowInterceptTouchEvent(true)`，拦截父容器滚动。
     - 随着手势拖拽，列表项自身跟随产生一定的横向弹性位移：`translationX = Math.min(dx * 0.4f, dp(48))`。
3. 当接收到 `ACTION_UP` 时：
   - 若 $dx > dp(56)$，正式触发 Pop-up 浮层呼出，同时 `translationX` 快速复位。
   - 若未达到阈值，平滑复位 `translationX = 0`。

### 3.2 浮层视觉与层级重塑：去边框毛玻璃微卡片与锚点跟随定位

原生 Niagara Launcher 的 Pop-up 不是粗糙的全屏弹窗，而是一个**与目标应用项几何锚定（Anchored）的悬浮微卡片**：
- **纵向锚定**：卡片顶点或中心垂直对齐目标列表项的 $Y$ 轴位置；若靠近屏幕底端，则自动向上翻转展开，避免被软键盘或导航栏截断。
- **横向留白**：左侧对齐应用图标中心（偏移 64dp），右侧距离屏幕边缘保持 16dp，确保单手拇指触达。
- **视觉风格**：去除厚重视窗边框与生硬投影。采用微透明深色背景（`#E61A1C20` 适配深色主题，`#E6F4F5F7` 适配浅色主题），圆角设为 `20dp`，带有细微的 `0.5dp` 高光内轮廓线。

### 3.3 通知中枢联动：未读通知摘要、内联快捷回复与 Dismiss 操作

依托 `NotificationHubService.java` 已有的未读缓存机制，Pop-up 展开时动态组装通知面板：

1. **通知数据检索**：
```java
List<NotificationHubService.NotificationInfo> notifs = NotificationHubService.getAllByPackage(appInfo.packageName);
```
2. **通知卡片内嵌渲染**：
- 渲染通知发布者、标题、内容摘要以及时间戳（如 `3m ago`）。
- **快捷动作按钮组**：解析 `Notification.Action`，若包含快捷回复（`RemoteInput`），渲染快捷回复输入框；若包含常规 Action（如“标记已读”、“删除”、“暂停”），动态渲染为扁平操作胶囊钮。
- **一键清除（Dismiss）**：右滑通知微条目即可调用 `NotificationHubService.cancelNotification(sbnKey)`。

### 3.4 原生应用动态快捷方式：`LauncherApps.getShortcuts()` 安全调用

在 Android 7.1+ (API 25) 上，利用系统服务 `LauncherApps` 动态抓取应用的静态与动态 Shortcuts：

```java
public static List<ShortcutItem> queryAppShortcuts(Context context, String packageName, UserHandle userHandle) {
    List<ShortcutItem> result = new ArrayList<ShortcutItem>();
    if (Build.VERSION.SDK_INT < Build.VERSION_CODES.N_MR1) return result;
    
    LauncherApps launcherApps = (LauncherApps) context.getSystemService(Context.LAUNCHER_APPS_SERVICE);
    if (launcherApps == null || !launcherApps.hasShortcutHostPermission()) return result;

    LauncherApps.ShortcutQuery query = new LauncherApps.ShortcutQuery();
    query.setPackage(packageName);
    query.setQueryFlags(
        LauncherApps.ShortcutQuery.FLAG_MATCH_DYNAMIC |
        LauncherApps.ShortcutQuery.FLAG_MATCH_PINNED |
        LauncherApps.ShortcutQuery.FLAG_MATCH_MANIFEST
    );

    try {
        List<ShortcutInfo> shortcuts = launcherApps.getShortcuts(query, userHandle);
        if (shortcuts != null) {
            for (ShortcutInfo s : shortcuts) {
                if (s.isEnabled()) {
                    result.add(new ShortcutItem(
                        s.getId(),
                        s.getPackage(),
                        s.getShortLabel() != null ? s.getShortLabel().toString() : s.getId(),
                        s,
                        userHandle
                    ));
                    if (result.size() >= 4) break; // 最多展示 4 个高频快捷方式
                }
            }
        }
    } catch (SecurityException ignored) {
        // 无 ShortcutHostPermission 或权限被收回时的安全防护
    }
    return result;
}
```

点击 Shortcut 时，通过 `launcherApps.startShortcut(packageName, shortcutId, sourceBounds, opts, userHandle)` 安全唤起。

## 4. 首屏留白美学与灵动搜索过渡 (`HeroStatusBarView.java` + `NiagaraCoinButton.java` + `AuroraBackdropView.java`)

### 4.1 顶部状态栏视觉减重（HeroStatusBarView）

在 `v2.5.0` 中，顶部包含了农历、天气、电量与多条细小分割元素，整体视觉偏拥挤。`v2.6.0` 实施全面去重与负空间排版重塑：
1. **去除生硬分割线条**：彻底移除 `|`、`·` 等字符级多余分割符，改用自然字距与水平间距（`8dp` 优雅空隙）。
2. **强化字重对比（Typography Rhythm）**：
   - 时钟：采用大号轻盈无衬线字体（`Sans-Serif-Light`，字号 `44sp`），呈现极简现代质感。
   - 日期与节气：采用中字重（`Sans-Serif-Medium`，字号 `14sp`），半透明浅白（`alpha = 0.85f`）。
   - 天气与温标：与农历平滑组合在次级文本行中，高度克制，不喧宾夺主。
3. **呼吸感负空间**：首屏列表起始内衬（Padding Top）动态联动时钟高度，保留至少 18% 屏幕高度的纯净天空留白区，让壁纸美感自然舒展。

### 4.2 悬浮灵动圆钮与搜索过渡动效（Coin Button & Search Transition）

在 Niagara 原生手感中，唤起全局搜索不仅是一个界面的切换，而是**整个屏幕空间的景深变换**：

```
[ 首屏常态 ]
  壁纸缩放: 1.0x ──────┐
  压暗遮罩: 0%  ──────┼── 点击 NiagaraCoinButton 或向上滑动手势
  搜索卡片: 隐藏 ──────┘
                       ▼
[ 搜索过渡态 (持续 220ms，贝塞尔平滑插值) ]
  壁纸缩放: 1.0x  ──▶ 0.96x (微后退视差景深)
  压暗遮罩: 0%   ──▶ 35%   (增强搜索列表可读性)
  Hero 时钟: 上滑淡出 (alpha: 1.0 -> 0.0, translationY: -30dp)
  搜索栏:   贴合软键盘升起轨迹从底部平滑跃升，光标自动闪烁
```

#### 壁纸景深渲染引擎 (`AuroraBackdropView.java`)
```java
// 为壁纸容器增加灵动过渡因数
private float mSearchProgress = 0.0f; // 0.0 (首屏) -> 1.0 (完全搜索态)

public void setSearchTransitionProgress(float progress) {
    this.mSearchProgress = Math.max(0.0f, Math.min(1.0f, progress));
    // 1. 微缩放变换矩阵
    float scale = 1.0f - 0.04f * mSearchProgress;
    setScaleX(scale);
    setScaleY(scale);
    // 2. 压暗半透明遮罩
    mDimPaint.setColor(Color.BLACK);
    mDimPaint.setAlpha((int) (255 * 0.35f * mSearchProgress));
    invalidate();
}
```

### 4.3 软键盘无缝对齐与检索零时延

在呼出全局搜索时：
1. **IME 软键盘联动**：使用 `WindowInsetsControllerCompat`（或底层原生 `WindowInsets`）监听键盘高度，搜索框动态设置 `translationY = -keyboardHeight`，保持输入框紧密粘合在键盘顶缘，杜绝闪烁或跳变。
2. **多模态搜索零时延流转**：
   - 首字符为数字或运算符（`+ - * / =`）：直接路由至 `QuickCalcEngine`，在第 0 项实时计算并展示算式结果微卡片。
   - 首字符为字母或汉字：并行执行 T9、前缀拼音全拼以及连续拼音模糊检索，结果通过 `DiffUtil` 原理局部刷新，响应耗时严格控制在 8ms 以内。

## 6. 异常边界与兼容性防错矩阵

| 场景 / 边界 | 潜在风险 | 严格防御策略（Java 8 规范） |
|---|---|---|
| **Android 10+ 侧滑返回冲突** | 在屏幕边缘滑动快速检索字母时，误触系统返回操作 | 1. 严格使用 `setSystemGestureExclusionRects` 动态锁定触点上下 90dp 区域。<br>2. `onTouchEvent` 在首个 `ACTION_DOWN` 时即刻调用 `getParent().requestDisallowInterceptTouchEvent(true)`。 |
| **低配设备过度重绘** | 列表项高频位移导致 Choreographer 掉帧 | 1. 仅对可见项计算位移（`layoutManager.findFirst/LastVisibleItemPosition`）。<br>2. 位移仅使用 `translationX` 与 `scale`（GPU 合成层属性），严禁触发 `requestLayout()`。 |
| **Shortcuts 权限受限** | 非默认桌面或 Android 7.1 以下调用崩溃 | 1. 严加 `Build.VERSION.SDK_INT >= Build.VERSION_CODES.N_MR1` 门禁。<br>2. 必须包裹在 `try ... catch (SecurityException | NoSuchMethodError)` 中安全降级。 |
| **通知快捷回复空指针** | 某些第三方通知 RemoteInput 结构不规范 | 提取 `RemoteInput` 时，层层校验 `getResultsBundle()` 与 `action.getRemoteInputs() != null`。 |
| **快速连击震动器过载** | 用户手指快速扫过多达 26 个字母导致马达震感粘连 | 设置 `12ms` 最小时间窗口阈值（Debounce Filter），防止震动序列堆积。 |

### 7.2 代码静态检查与语法合规性红线
- 严禁引入任何 Java 9+ 语法：
  - ❌ 禁止 `var list = new ArrayList<>()`
  - ❌ 禁止 `List.of(...)` / `Map.of(...)`
  - ❌ 禁止 `switch` 表达式 / 文本块（Text Blocks）
- 严禁引入外部 `androidx.*` 命名空间库，全部使用 `android.*` 原生框架 API。
- 严禁重命名 `.java` 文件而不同步修改顶层类声明及全工程所有引用。
